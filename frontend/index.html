The four ideas behind the project

Short explanations in simple words.

What is Secure File Segmentation?

A big file is cut into equal blocks (5 MB here). Each block gets an index number, is sent separately, and can be retried if it fails. After download the blocks are joined in index order to rebuild the exact original file.

What is AES-256 Encryption?

AES is a standard cipher; 256 means a 256-bit secret key. In GCM mode it also adds a 16-byte authentication tag, so if anyone changes even one bit of a stored block, decryption fails instead of giving wrong data.

What is Cloud Storage?

Object storage such as Amazon S3 keeps files as objects inside buckets. It is durable, pay-as-you-go and needs no server. Here the bucket is private and holds only encrypted segments.

What is a CDN?

A Content Delivery Network (Amazon CloudFront) keeps copies of your website at edge locations near visitors. Pages load faster, the origin bucket gets less traffic, and HTTPS is provided.

Main features

Everything required by the project report, implemented as working software.

Client-side keys

A random 256-bit key is created in your browser. It is never sent to the server or cloud and never put in localStorage. You save it as a key file.

Tamper detection

The segment index is authenticated data. Wrong keys, changed bytes, swapped or missing segments are detected and no broken file is produced.

Presigned URLs

AWS keys stay on the Python backend. The browser talks to S3 using short-lived signed links, one per segment.

Real dashboard

File counts, segments, storage used and activity come from the actual stored data, not from fixed numbers.

Measured performance

Segmentation, encryption, upload, download, decryption and rebuild times are measured per transfer. CDN cache status is read from real response headers.

S3 + CloudFront hosting

The site is stored in a private S3 bucket, reachable only through CloudFront over HTTPS, with index.html and error.html.

How the system works

Upload and download, step by step.

Upload

1
Choose a file. The browser creates a new random 256-bit key.
2
The backend returns one presigned URL per segment (part00000.enc, part00001.enc …).
3
For each 5 MB block: encrypt with a fresh 12-byte nonce, then PUT the ciphertext straight to S3.
4
The backend checks every stored object size, writes a manifest, and you save your key file.

Download

1
Pick a file and provide your key file (or key text).
2
The browser fetches each encrypted segment through a presigned URL.
3
Every segment is decrypted and its tag and index are verified. Any failure stops the process.
4
Verified segments are merged in order and you download the restored original file.
