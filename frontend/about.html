System architecture

Browser (client)split · AES-256-GCM · key stays here
Flask backendpresigned URLs · manifest · activity log
AWS S3 (private)encrypted segments only
Website filesHTML · CSS · JS
S3 site bucket (private)index.html · error.html
CloudFront CDNHTTPS · edge cache · OAC

File data goes browser → S3 directly using presigned URLs; the backend never sees file contents or keys. The website is delivered S3 → CloudFront → visitor.

Security: what is implemented

  • AES-256-GCM per segment; fresh random 12-byte nonce; 16-byte tag; index as authenticated data.
  • Key generated in the browser; never sent to the server, never in localStorage; exported by the user.
  • S3 bucket private; short-lived presigned URLs; AWS credentials only in the backend.
  • Wrong key, modified, truncated, swapped or missing segments are detected; no restored file is produced.
  • Server checks every stored segment size before it accepts an upload.

Limitations (honest list)

  • File names, sizes and upload times are visible in the manifest and S3 keys (contents are not).
  • No user login: anyone who can reach the backend can list and delete files. Add authentication before real use.
  • Lost key = lost data. There is no recovery.
  • The restored file is assembled in browser memory, so very large files need enough RAM (limit set by MAX_FILE_MB).
  • Browser protection depends on the page code you deploy being trustworthy (served over HTTPS from your CloudFront).

Static website hosting and CDN

The website files are stored as objects in an S3 bucket with index.html as the home page and error.html as the error page. The bucket stays private; CloudFront reads it using Origin Access Control (OAC), so nobody can bypass the CDN.

How CloudFront delivers content: a visitor's request goes to the nearest edge location. If the file is in that edge cache (a hit) it is returned immediately. If not (a miss) the edge fetches it once from S3, returns it, and keeps a copy for the next visitors. CloudFront also serves everything over HTTPS.

After you update the website, deploy and clear the CDN cache:

python scripts/deploy_site.py --invalidate
# or manually:
aws s3 sync frontend s3://YOUR_SITE_BUCKET --delete
aws cloudfront create-invalidation --distribution-id YOUR_DISTRIBUTION_ID --paths "/*"

Encrypted file segments are downloaded with presigned S3 URLs (not through the CDN cache), which keeps access short-lived and private. See the README for full AWS setup.
